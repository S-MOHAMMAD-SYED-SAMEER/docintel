# invoices_hard_v1

Ten **synthetic** invoices that are harder to read than `invoices_v1`, generated by
`evals/generate_invoices_hard_v1.py`. Vendors, customers, addresses, tax ids and amounts are invented; no real
document is included, and no claim is made about real-world accuracy.

**Provenance (the label that goes with every number from this set):** *Written by Claude (generated; labels are
the render inputs); reviewed by ChatGPT and Claude; final decisions by Sameer.* The review (every field of every
document, by ChatGPT, and my own check) found no wrong label and no unreadable document; Sameer approved the set
on 2026-10-21 with no label changes.

**Frozen.** The set was frozen before any real-model run. `docs/EVAL.md` records its sha256
(`python -m evals.freeze invoices_hard_v1`) and `tests/test_hard_set_frozen.py` fails if any file here differs.
A change after a model has seen it is a new dataset version, never an edit.

## What is in it

| Document | Kind | Why it is hard |
|---|---|---|
| hard-001.png | scan | skewed 2.5 degrees, blurred and noisy; image only |
| hard-002.png | image | day-first dotted dates, decimal commas and thousands dots, a euro sign and no currency code; image only |
| hard-003.pdf | text PDF | 04/03/2026 could be April 3 or March 4; the due date 18/03/2026 shows day-first; totals first |
| hard-004.pdf | text PDF | a credit note: negative quantities and amounts, in brackets |
| hard-005.jpg | photograph | low resolution, compressed, a shadow across the lower half; image only |
| hard-006.pdf | text PDF | eight rows over two pages, the totals only on page two |
| hard-007.pdf | text PDF | a freight row inside the table; a Total-due line first; Net/VAT/Gross wording |
| hard-008.png | image | an order number and an account number beside the invoice number; Ship-to differs from Bill-to; a payment processor named first |
| hard-009.pdf | text PDF | no due date ("Payable on receipt"), no tax id, no purchase order; tax of 0.00 (reverse charge) |
| hard-010.png | scan | a semi-transparent PAID stamp across the totals, a scribble, a coffee ring; image only |

Five are images with **no text layer**, so the text-layer check can never corroborate a value there. The five PDFs do
have one. `FEATURES.json` holds the same descriptions in machine-readable form.

## Two scoring rules, decided with the approval and before any run

1. **Credit note (hard-004).** A line item whose amount is negative is correct if the amount is the correct negative
   value, whether the minus is written on the quantity or on the unit price (`evals/metrics.py`).
2. **"Payable on receipt" (hard-009).** The correct `due_date` is null. A model that fills in a date (the invoice date, say)
   is scored wrong; an absent value matches only another absent value.

## Limits

Ten documents from a small invented pool of vendors and customers, with one font family per kind: a smoke test with
some teeth, not a benchmark. The difficulty was set by hand, not measured. Labels are by construction and were reviewed
by an AI and a person, not independently annotated. One run of each prompt, one model.

Regenerating (`python -m evals.generate_invoices_hard_v1`) does not reproduce the committed bytes (image encoders and
the system font differ between machines); the committed files are the dataset.
