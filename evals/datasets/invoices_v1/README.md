# invoices_v1

Twenty **synthetic** invoices, generated by `evals/generate_invoices_v1.py`.

Vendors, customers, addresses, tax ids and amounts are invented. No real
invoice is included, and no claim is made about real-world accuracy: these are
clean, born-digital PDFs with a proper text layer, which is the easiest case
the pipeline will ever see. A scan, a photo, or a badly laid-out invoice will
score worse.

What the dataset does measure honestly: whether extraction reads a legible
invoice correctly, whether the deterministic checks catch a wrong total, and
what a document costs and takes.

`labels.json` is authoritative. Each record's fields are the values used to
*render* the PDF, so the labels describe what the document says — never what a
model claims it says. Every invoice is internally consistent: line items sum to
the subtotal, and subtotal + tax = total.

Regenerate with:

```bash
python -m evals.generate_invoices_v1
```

The committed PDFs are the dataset. Regenerating changes it, so a run before
and a run after are not comparable unless the generator is unchanged.
