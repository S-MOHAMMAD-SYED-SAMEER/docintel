# purchase_orders_smoke

Three **synthetic** purchase orders, generated by
`evals/generate_purchase_orders_smoke.py`.

This is a smoke fixture, not a benchmark. It exists to prove that the
evaluation harness — and the extraction, validation, confidence, review and
export pipeline behind it — carries a second document type end to end. **No
accuracy claim should be made from three documents.**

`labels.json` declares `"doc_type": "purchase_order"`, which is how the runner
selects the purchase-order schema, prompt and validator. As with the invoice
dataset, the labels are the values used to render each PDF, so they describe
what the document says rather than what a model claims it says. Every order is
internally consistent: line items sum to the subtotal, and subtotal + tax =
total.

Regenerate with:

```bash
python -m evals.generate_purchase_orders_smoke
```
